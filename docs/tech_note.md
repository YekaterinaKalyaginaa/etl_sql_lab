# Техническая записка

## Общая информация

Проект посвящён построению витрины данных с использованием подходов DWH:
- слой источника данных (DDS),
- слой витрины данных (DM),
- слой контроля качества данных (DQ).

В качестве СУБД используется PostgreSQL.
Данные являются синтетическими и генерируются внутри базы данных.

---

## Предметная область

Рассматривается профиль клиента.
Каждая запись описывает клиента и содержит следующие атрибуты:
- идентификатор клиента,
- ФИО,
- пол,
- возраст,
- город,
- сегмент клиента,
- ежемесячный доход,
- дата регистрации,
- период действия записи (valid_from, valid_to).

Данные могут содержать аномалии:
- пропуски значений,
- некорректные даты,
- текстовые значения в числовых полях,
- дубликаты записей.

---

## Лабораторная работа 1 — ETL (DDS)

На первом этапе реализован процесс Extract–Transform–Load.

1. Генерация синтетических данных производится SQL-функцией  
   `s_psql_dds.get_dataset(n)`.

2. Сырые данные загружаются в таблицу  
   `s_psql_dds.t_sql_source_unstructured`,  
   где все поля имеют тип VARCHAR.

3. Очистка и приведение типов выполняется функцией  
   `s_psql_dds.fn_etl_data_load(start_date, end_date)`.

4. Результат загружается в таблицу  
   `s_psql_dds.t_sql_source_structured`  
   с корректными типами данных.

В рамках ETL выполняется:
- нормализация строк,
- безопасный парсинг дат и чисел,
- обработка ошибочных значений,
- удаление дубликатов.

---

## Лабораторная работа 2 — Витрина данных (DM)

На основе структурированных данных реализована витрина данных
по схеме «звезда».

Созданы справочники:
- `t_dim_gender`,
- `t_dim_city`,
- `t_dim_segment`.

Создана факт-таблица:
- `s_psql_dm.t_dm_task`.

Загрузка витрины выполняется функцией:
- `s_psql_dm.fn_dm_data_load(start_dt, end_dt)`.

Для аналитического доступа создано представление:
- `s_psql_dm.v_dm_task`.

---

## Лабораторная работа 3 — Контроль качества данных (DQ)

Для витрины реализован контроль качества данных.

Создана таблица логирования:
- `s_psql_dds.t_dq_check_results`.

Реализована функция:
- `s_psql_dds.fn_dq_checks_load(start_dt, end_dt)`.

Выполняются следующие проверки:
1. Полнота идентификатора клиента (customer_id).
2. Уникальность customer_id.
3. Валидность сегмента клиента.
4. Непротиворечивость дат valid_from и valid_to.
5. Корректность количества строк между structured и витриной.

Для визуализации результатов создан дашборд:
- `s_psql_dds.v_dq_dashboard`.

Также реализован базовый механизм алертинга:
- `s_psql_dds.v_dq_alert`.

## Инструкция по запуску проекта

### Шаг 1. Загрузка данных (DDS)

```sql
select s_psql_dds.get_dataset(300);
select s_psql_dds.fn_etl_data_load('1900-01-01', '2100-01-01');
```

### Шаг 2. Формирование витрины (DM)
```sql
select s_psql_dm.fn_dm_data_load('1900-01-01', '2100-01-01');
```
### Шаг 3. Контроль качества данных (DQ)
```sql
select s_psql_dds.fn_dq_checks_load('1900-01-01', '2100-01-01');
select * from s_psql_dds.v_dq_dashboard;
select * from s_psql_dds.v_dq_alert;
```
